# Realized Stochastic Volatility Models with Skew-t Distributions for Volatility and Tail Risk Forecasting

Replication code for

> Takahashi, M., Yamauchi, Y., Watanabe, T., and Omori, Y. *Realized Stochastic Volatility Models with
> Skew-t Distributions for Volatility and Tail Risk Forecasting.* Submitted for publication.
> Preprint: [arXiv:2401.13179](https://arxiv.org/abs/2401.13179).

**Scope.** This repository contains the **source code only**: the Ox programs that estimate the SV and
RSV models by MCMC and produce the rolling one-day-ahead forecasts, and the R scripts that construct
the data, evaluate the forecasts (QLIKE, Giacomini-White tests, model confidence sets, VaR/ES losses)
and produce every table and figure of the article and of the Supplementary Material. Input data are not
redistributed (see [`Data/README.md`](Data/README.md)); the MCMC output (tens of GB) is regenerated by
the scripts and is not stored here. The Bayesian EGARCH/REGARCH benchmarks were estimated with a
separate program (see section 5) and enter the evaluation as external forecast files.

**What changed in the October 2026 revision.** Readers of earlier versions of the preprint
should note three corrections, all documented in the Supplementary Material of the revised version:
(i) the one-day-ahead forecasting step of `SVGH.ox` contained a coding error (fixed 2026-09-16; all
SV-GH-ST forecasts regenerated); (ii) the forecasting step of `RSVAZ.ox`/`SVAZ.ox` standardized the
truncated-normal leverage term by `sqrt(1-c^2)` instead of `sqrt(1-delta^2)` (fixed 2026-09-26; all
Azzalini forecasts regenerated with the dual-output classes in `Ox/az_recomputation/`, with
multi-chain convergence checks); (iii) the rolling Hansen-Lunde adjustment of the evaluation proxies
was not aligned with the estimation window and the forecast target day (fixed 2026-09-28; previous
scripts kept in `R/previous_versions/`). All volatility forecasts are evaluated with the predictive mean.

> The code is consolidated into two top-level folders, `Ox/` and `R/`, each kept
> flat so the scripts' relative paths keep working: the Ox scripts use
> `#include<RSVAZ.ox>` and `loadmat("../Data/...")`, the R scripts use
> `source("function_*.R")`, `../Data/` and `../Ox/`. Run Ox scripts from inside
> `Ox/` and R scripts from inside `R/`. See `Ox/README.md` and `R/README.md` for the per-file map.

## 1. Models

Stochastic volatility (SV) and **realized** SV (RSV) models with several skew-t
return distributions, plus GARCH-type benchmarks.

| Paper label   | Family / class                         | Source file (flags)                                   |
|---------------|----------------------------------------|-------------------------------------------------------|
| (R)SV-N       | Normal                                 | `RSVAZ`/`SVAZ` with `fls=0,flt=0`                     |
| (R)SV-T       | Student-t                              | `RSVAZ`/`SVAZ` with `fls=0,flt=1`                     |
| (R)SV-AZ-SN   | Azzalini skew-normal                   | `RSVAZ`/`SVAZ` with `fls=1,flt=0`                     |
| (R)SV-AZ-ST   | Azzalini skew-t                        | `RSVAZ`/`SVAZ` with `fls=1,flt=1`                     |
| (R)SV-FS-SN   | Fernández–Steel skew-normal            | `RSV_skewFS` with `SetIsT(0)`                          |
| (R)SV-FS-ST   | Fernández–Steel skew-t                 | `RSV_skewFS` (default)                                 |
| (R)SV-GH-ST   | Generalized-hyperbolic skew-t          | `RSVGH`/`SVGH`                                         |
| EGARCH-N/T    | Benchmark (Bayesian)                   | estimated externally — see note in §5                 |
| REGARCH-N/T   | Benchmark (Bayesian, realized GARCH)   | estimated externally — see note in §5                 |

Measurement (log-RV) equation of the RSV models:
`x_t = xi + psi * h_t + u_t`, `u_t ~ N(0, sigma_u^2)`, with `h_t` the
log-volatility. In the baseline models `psi` is fixed at 1; see §4 for the
free-`psi` extension added in this revision.

## 3. Reproduction pipeline

1. **Build data** (`R/`, see [`Data/README.md`](Data/README.md))
   `construct_data_{djia,n225}.R`, `construct_rv_hl_*.R`
   → processed CSVs in `Data/`.

2. **Estimate & forecast** (Ox, rolling 1-step-ahead, run from `Ox/`)
   e.g. `oxl rsv_gh_st_n225_prediction.ox`. Each model/index writes per-window
   posterior summaries and VaR/ES/volatility forecasts into an output folder
   (e.g. `N225_prediction/`). The Fernández–Steel models run from
   `Ox/` (use `copy_oxfile.sh` + `runpred.sh` for the parallel
   rolling prediction). **This is the expensive step — days of MCMC on a
   server; see §6.**

3. **Merge forecasts** → `prediction_results_2026/`
   Ox: `merge_prediction_results_{az,gh}.ox`; R: `merge_prediction_results_2026.R`
   (COVID: `merge_prediction_results_n225_2020.R`,
   `merge_prediction_results_fs_n225_2020.R`).

4. **Evaluate** (`R/`)
   - Volatility: `examine_forecast_vol_2026.R` — MSE, QLIKE, Giacomini–White
     tests, and the **Model Confidence Set** (Hansen, Lunde & Nason, 2011).
   - Tail risk: `examine_forecast_var_es_2026.R` — violation rates, Dynamic
     Quantile test, FZ0 loss, GW tests, MCS.
   - COVID period: the `*_n225_2020.R` counterparts.
   The MCS is reported at **both the 75% and 90% confidence levels** (`**` = 75%
   MCS, `*` = 90% MCS); the MCS p-value is level-independent, so both sets are
   read off the same p-value.
   **To reproduce the tables of the article set `RSVST_HL=r3corrected` and `RSVST_AZ=dualfixed`**
   (see `R/README.md`, "Environment variables"); the exclusion sensitivity uses `RSVST_MASK_DIR`.

5. **Tables & figures** (`R/`)
   `summarize_forecast_vol_2026.R`, `summarize_prediction_results_2026.R`,
   `output_forecast_vol_2026.R`, `output_forecast_*_gwtest_2026.R`
   (LaTeX); `plot_forecast_vol_2026.R`, `plot_var_es_2026.R`,
   `fig_dens_analytic_2026.R` (density figures).

6. **Simulation study** (Ox, `Ox/`)
   `rsv_*_simulation.ox` — generates data from known parameters and checks
   posterior recovery.

## 4. Free-`psi` extension (sensitivity analysis)

Comment 2 of the review asks to estimate the log-RV slope coefficient `psi`
rather than fixing it at 1. This is provided as a **sensitivity / robustness**
analysis for all RSV models.

- **Azzalini family** (`RSVAZ`): a Gibbs block for `psi` was added
  (`SetBC(1)`, `SampPsi`). New rolling-forecast scripts:
  `rsv_{n,t,sn,st}_psi_{djia,n225}_prediction.ox`
  (named `rsv_az_*_psi_*`).
- **GH family** (`RSVGH`, already supported `SetBC`): `rsv_gh_st_psi_*_prediction.ox`.
- **Fernández–Steel family** (`RSV_skewFS`): `SetIsPsi(1)` / `SamplePsi` added;
  `RSV_skewFS_run_psi.ox`.

Each free-`psi` model writes the posterior of `psi` alongside the other
parameters; set `flbc=1` / `SetBC(1)` / `SetIsPsi(1)` to enable it. The baseline
(`psi = 1`) scripts are unchanged and remain the main results.

> Validation: with simulated data (true `psi = 1.25`) the samplers recover
> `psi ≈ 1.25` (AZ and FS classes), confirming the new Gibbs steps.

## 5. GARCH benchmarks

The EGARCH-N/T and REGARCH-N/T benchmarks were estimated **with a separate Bayesian program**
(provided by a co-author) that is not part of this repository; their volatility, VaR and ES
forecasts enter the R evaluation as external files (`REGARCH_Bayes/*.xlsx`, not distributed here).
The RSV/SV rows of every table are fully reproducible from this repository; the GARCH rows require
those forecast files.

## 6. Software & runtime

- **Ox** 9.x (Console; the runs of the article used Ox 9.10 on Linux), Doornik (2007). Scripts include
  `oxstd`, `oxprob`, `oxfloat`, `oxdraw`, and (for FS) the `maximize` package.
  Run with `oxl <script>.ox` from the directory containing the script.
- **R** (≥ 4.x) with packages: `MCS`, `sandwich`, `tidyverse` (incl. `readr`,
  `ggplot2`), `reshape2`, `readxl`, `ggrepel`, `ggnewscale`.
- **Runtime:** the rolling MCMC estimation (≈ 590 windows × 7 RSV/SV models ×
  2 indices, plus the COVID sample and the free-`psi` variants) is heavy and was
  run on a server over several days. The simulation study and the R
  evaluation/figure scripts run on a desktop in minutes once the forecasts
  exist. The FS models default to 90,000 MCMC draws (60,000 burn-in) per window
  and need substantial memory — reduce these for a desktop smoke test.
